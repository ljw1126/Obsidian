
## 오전 (261121)

**돌아볼 질문**
1. AI가 만든 코드가 맞는지 무엇으로 확인했는가?
2. 다 만든 뒤 고치려 할때 무엇이 깨질까 걱정했는가?
3. 무엇을 AI에게 맡기고, 무엇을 내가 정했는가 ?


**무엇이 걱정됐을까?**
- 어디서 사용되는지 모르는 코드
- 확인할 테스트가 없는 기능
- AI가 만들어서 내가 설명할 수 없는 코드
- 고친 뒤 무엇을 확인해야 하는지 모르는 변경

- 의도 부채
	- 결과물과 코드가 어떤 의도를 가지고 도출되었는지 모르는것 
- 인지 부채
	- 있는지 몰랐다..

>  AI에 대한 기술 부채가 내년에 발생 예상 (1년치)
- 생산되는 결과물을 쏟아지는데 어떻게 관리할 것인가 (사람의 영역)
	- 엔지니어와 개발자의 역할이 shifting 한다.

> 엣지 케이스 테스트 필요

> 인터페이스를 언제 만들어야 할까? 왜 만들어야 할까 ?
- `추상화`?
- 인터페이스를 `추상화, public API, Spec`로 표현하기도 한다  
- 쉽게 갈아 끼울 수 있다는건 
	- **테스트 하기 쉬워진다.**

> 테스트는 동료들을 위한 코드이다. 동료가 읽기 좋게 테스트 코드를 유지보수해야 한다.  
- 이와 반대가 되면 고통을 받게 된다. 


**관찰할 것**
- 상태 코드만 확인하는 내 테스트는 몇 개인가?
- 실패한 요청 뒤의 상태를 확인하는 테스트가 있는가?
- 외부 API가 실패하는 경우를 테스트 했는가?

> 토스 Payment 
- 이런 실패 응답 값을 나에게 돌려줘를 설정 가능하다 
- 그렇기 때문에 다양한 시나이로를 테스트 할 수 있어 좋다.


> 비속어 검사에 대한 실패 사유에 대한 기준을 세우고, 기록(컨벤션, 정책)으로 관리할 수 있다. 
- AI가 이런 것도 참고 가능하다.
