**LLM Wiki 설계** 
> AI는 이해의 대리인이 아님
> 이해를 쌓는 도구로 써야 함


**3 레이어**
- RAG의 한계 
	- 지식의 누적이 안됨 (같은 문서 기반으로 답변)
	- 여러 문서를 종합하는 추론이 약함
	- 복리 효과가 없음 
- Karpathy의 통찰 (OpenAI )
	- https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
	- `새 자료가 들어올 때마다 검색용으로 저장하는게 아니라, LLM이 직접 읽고 기존 위키에 통합해 넣게 하라`

**우리의 역할** 
- 소스 수집 
- 탐색 
- ✅ 올바른 질문을 던짐

**어디에 활용하는가?**
- 개인용
- 리서치
- 책읽기
- 비즈니스/팀
- 경쟁 분석, 실사, 여행 계획, 강의 노트, 취미 심층 탐구 ...

```text
wiki
|-- raw/
     |--- articles
     |--- papers
     |--- notes
|-- wiki/
     |--- concepts
     |--- java
     |--- kafka
|-- schema : 이 위키가 어떻게 구성되어 있는가? (claude.md)
```
- `raw/` : 수정하지 않는다, 읽기만 한다 (쓰기는 LLM이 한다)

**3가지 기본 작업**
- Ingest : 새 자료가 생겼을때 LLM은 raw를 읽고 요약을 하고 기존 페이지를 업데이트
- Query : wiki가 어느정도 쌓이면 자유롭게 질문 
	- 탐구 자체가 지식 베이스의 일부 >> 지식의 복릭가 됨
- Lint : 주기적으로 수행하는 장비

> index.md : wiki에 있는 모든 것의 카탈로그 
> log.md : 무엇이 언제 일어났는지 append-only

**정리**
- LLM 위키는 자료가 들어올때마다 구조화된 지식으로 편찬
	- 커스터마이징, 튜닝하면 된다 (정답이 없다)
		- 방향성은 이렇게 하고

`CLAUDE.md`를 어떻게 쓰면 되나요?
- 200줄 이하로 목표 (짧게 유지)
- 마크다운 헤더와 글머리 기호를 사용하여 그룹화 
- 검증 가능하도록 구체적인 지침을 작성 
- API키, 비밀번호, 인증번호는 넣지 말 것


```text
나는 옵시디언 볼트를 LLM Wiki 방식으로 운영하려고 해. LLM Wiki.md 참고해서 디렉터리와 초기 파일을 생성해줘. #추가로 내비게이션 역할을 하는 MOC (Map Of Content) 방식을 넣어줘. 그리고 CLAUDE.md 파일 초안을 잡아두었는데 이 파일도 같이 업데이트해줘.
```
